# 에이전트 도구 생태계 — 2026년 7~9월

## 요약
에이전트 도구 생태계가 빠르게 분화하고 있다. 브라우저 자동화, MCP 서버, 터미널 작업 등 각 영역별 전문 도구가 등장하면서, 에이전트 개발 스택이 성숙 단계에 진입했다. MCP(Model Context Protocol)가 200+ 서버 구현체를 확보하며 사실상 표준으로 자리잡았고, 도구 간 상호운용성이 빠르게 표준화되고 있다. 8월에는 코딩 도구가 에디터를 넘어 코드 호스팅·소프트웨어 팩토리·추론 배포까지 개발 파이프라인 전 계층의 인프라로 확장하고 있다. 동시에 교육·에이전트 평가·가정 운영 등 개발 스택 밖 영역으로 AI 도구가 확산 중이다. 8월 말에는 도구 스택 전체를 하드웨어에 싣는 로컬-first 플랫폼(Perplexity Portable Computer)과 물리 세계 무인 운영(Gatik)으로 실행·적용 경계가 확장되는 동시에, 기능 분화가 만드는 브랜딩 파편화(Gemini)로 경험 경계의 역행도 함께 나타났다. 9월 첫째 주에는 생태계 주변부 3개 계층이 동시에 상업화됐다 — 스킬·MCP 서버를 지속 검증하는 에이전트 공급망 보안(AIR), 행동 묘사만으로 학습 데이터셋을 합성하는 생성 API(Adaption Labs), 소비자 개인 미디어 라이브러리를 직접 운영하는 개인 에이전트(Gemini Spark)가 그것이다. 이어 저작권 소송 압력이 도구의 정책 계층에 도달했다 — Claude 시스템 프롬프트가 가사·캐릭터 방어 조항으로 재편되며, 프롬프트가 곧 정책 엔진으로 기능하는 첫 실측 사례가 공개됐다. 9월 둘째 주에는 도구 스택의 양 끝에서 대형 벤더의 관리형·공식 도구가 동시에 나왔다 — 모델 앞에서는 의미 기반으로 호출 자체를 없애는 시맨틱 캐시(Redis LangCache, 비용 최대 90% 절감)가 16차 비용 3계층에 '응답 재사용'의 제4계층을 추가했고, 모델 뒤에서는 코딩 에이전트가 쓴 코드를 검증·패치·재공격하는 보안 스킬 툴킷(Google Mantis)이 보안의 스킬 내재화를 완성했다(24차). 이어 도구의 통합 계층이 위·아래로 동시 확장됐다 — 물리 AI의 '3 컴퓨터 문제'(훈련·시뮬레이션·실기 검증)를 단일 YAML·K8s 컨트롤 플레인으로 묶는 NVIDIA OSMO 오픈소스와, 기업 플랫폼의 '설정 노동'(계정 개설·API 등록·템플릿·웹훅)을 코딩 에이전트에 위임하는 WhatsApp Business Tools MCP가 같은 이틀에 나왔다(25차). 이어 MCP로 연결할 수 있는 대상의 지도가 양쪽 끝으로 확장됐다 — Google Home MCP 서버가 소비자의 물리 공간(기기·카메라·이벤트 기록)을 열었고, UN System Data Commons가 국제기구의 권위 있는 통계를 출처 추적과 함께 공급하기 시작했다(26차). 이어 에이전트와 맺는 '계약'의 3개 계층이 같은 이틀 사이에 정비됐다 — 지시는 파일 하나(AGENTS.md)로 표준화되고(Claude Code 합류), 권한은 소비자 공간으로 위임됐으며(구글 CC의 가족 계정·메타 Muse의 데스크톱 옵트인), 판단은 전문 소형 모델로 분업됐다(Cua CUA-S1)(27차). 이어 넷째 주에는 인간과 에이전트가 만나는 접점 자체가 3개 층위에서 동시 제안됐다 — 입력 층위에서는 음성이 워크 탭의 에이전트 워크플로를 말 한마디로 시작하게 됐고(ChatGPT 모바일), 협업 층위에서는 에이전트가 고유 신원과 수신함을 가진 팀원으로 채널에 입장했으며(Ando), 검토 층위에서는 인간과 에이전트가 같은 캔버스에서 설계 diff를 검토하고 결정 궤적을 감사하는 도구가 오픈소스로 나왔다(Whiteboard)(28차). 이어 29차는 그 접점 아래 깔리는 계약·통제의 하부구조가 동시 공개된 갱신이다 — 코딩 에이전트 5개 브랜드의 계약 문서를 읽어 IP 배상·프롬프트 보관·500석 비용을 대조한 첫 조달 기준표(GitHub Copilot·AWS Kiro 무상한 배상 vs Cognition의 Outputs 배상 제외, 6/1부 사용량 크레딧제 전환)와, 에이전트를 실행 환경 밖 DPU에서 밀리초 단위로 격리하는 NVIDIA Open Agent Safety Platform(OpenShell+Sentry, 100개 이상 조직·OpenAI 부재)이 한 세트를 이뤘다(29차). 이어 30차는 그 접점·계약 아래 도는 부품과 관리 계층이 같은 이틀 사이에 나온 갱신이다 — 에이전트가 소비하는 검색을 통째로 자체화한 Rust 엔진(Perplexity Photon, p99 800ms→65ms·Fast 모드 68% 절감), 에이전트에게 신원·주인을 부여하는 보안 플랫폼(RSA Agent ID, "은행에서 섀도 에이전트 4,000개"), 행동 감시 비용을 $372→$2.94로 끌어내리는 판단 API(OpenAI Decisions API), 그리고 판매자가 대화만으로 실제 스토어 코드를 고치는 버티컬 빌더(Shopify Canvas)가 한 세트를 이뤘다(30차). 이어 31차는 에이전트가 도는 장소 자체가 클라우드 과금 밖으로 내려앉는 갱신이다 — 토큰당 과금 없는 책상 위 하드웨어(DGX Spark 64GB, 시작가 $4,999·2대 QSFP 클러스터로 128GB), 인터넷에서 단절된 폐쇄망까지 내려가는 코딩 에이전트 플랫폼(IBM Bob 자체 호스팅, 모델 번들 없음), '14만 토큰 프롬프트+6천 토큰 증분'이라는 에이전트 터을 설계 기준으로 삼은 오픈 모델 서빙(Prime Inference, prefill/decode 분리·p90 40% 감소)이 같은 주에 겹쳤다. 이어 32차는 에이전트가 세상과 만나는 '나가는 쪽' 3개가 같은 주에 점검된 갱신 — 개인 데이터의 출력 경로(개인 CFO 에이전트가 은행 잔고를 회사 Slack에 게시한 첫 유출 사고, 읽기 전용 권한으로는 막을 수 없음), 모델 내부 신호의 감시 비용(Goodfire 프로브 $51 vs 최상위 LLM 판사 $10,000), 결정 출력의 가격(OpenAI Decisions API 공개 베타, $0.10/MTok·출력 과금 없음·약 10배)이 한 세트로 관측됐다.

## 2026년 9월 25차 갱신: 접착 스크립트의 소멸 — 물리 AI 3계층과 비즈니스 설정의 동시 통합

24차가 모델 주변의 가드(호출을 없애는 캐시·코드를 지키는 스킬)였다면, 25차는 통합 계층이 위(물리 AI 인프라)와 아래(기업 플랫폼 설정)로 동시에 뻗은 갱신이다. 공통 키워드는 '접착 코드의 제거' — NVIDIA는 훈련·시뮬레이션·실기 검증 사이의 접착 스크립트를, Meta는 개발자 콘솔·비즈니스 매니저 사이의 수동 설정 노동을 각각 오케스트레이션 계층으로 흡수했다.

### NVIDIA OSMO — 물리 AI의 '3 컴퓨터 문제'를 단일 YAML로 묶다 ⭐⭐⭐⭐

**출처**: [MarkTechPost — NVIDIA 공식 저장소·문서 교차 확인](../records/2026-09-15-nvidia-osmo-physical-ai-orchestrator.md) (9/14, Apache 2.0)

- **구조**: 훈련(GB200/H100)·시뮬레이션(Isaac Sim/RTX)·실기 검증(Jetson)의 3계층을 Kubernetes 네이티브 컨트롤 플레인 하나로 통합하는 오픈소스 워크플로 오케스트레이터. 파이프라인 전체를 단일 YAML로 기술하면 클러스터 이름이 아니라 **플랫폼**(gb200/rtx-pro-6000/jetson-agx-thor) 지정만으로 해당 풀에 라우팅 — 하드웨어 수명 주기가 다른 자원을 하나의 의존성 그래프로 묶는 컨트롤 플레인 분리
- **실무 구성**: KAI Scheduler 기본·NVLink 토폴로지 인식 배치, multi-provider 배포(6.3.0 — AKS/EKS/microk8s, 노트북 KIND에서 에어갭 클러스터까지), RBAC 사이드카·OAuth2 프록시·클라우드 워크로드 아이덴티티, HIGH/NORMAL/LOW 우선순위·선점·GPU 빌림, 콘텐츠 주소형 데이터셋(스토리지 10~100배 절감 주장 — 프로젝트 문서). GR00T·Isaac Lab/Sim/ROS 실전 검증
- **에이전트 내재화**: 저장소에 AGENTS.md·skills 디렉터리·MCP 배포 가이드 내장 — GTC 2026에서 OSMO가 Claude Code·Codex·Cursor와 통합돼 코딩 에이전트가 파이프라인을 제출·감시·디버깅. '에이전트가 개발 인프라를 조작하는' 패턴의 로봇 도메인 확장
- **위치**: [MCP 생태계](#mcp-생태계-확장-2026년-6월7월)·AGENTS.md 확산 축 + 물리 AI 스택의 오케스트레이션 완성편 — 오픈소스 공개는 파이프라인 전체를 NVIDIA 하드웨어(GB200→RTX→Jetson) 생태계에 고정하는 플랫폼 락인 전략으로도 읽힘

### WhatsApp Business Tools MCP — '설정 노동'이 에이전트의 몫으로 ⭐⭐⭐

**출처**: [TechCrunch](../records/2026-09-16-meta-whatsapp-business-tools-mcp-server.md) (9/15 발표)

- **내용**: Claude·Cursor·Codex·ChatGPT 같은 코딩 에이전트가 WhatsApp Business의 회사 계정 생성·전화번호 인증·Cloud API 등록·약관 확인은 물론, 메시지 템플릿 작성·편집, 웹훅 테스트, 그리고 그동안 **조용히 실패하던 항목**(약관·결제 수단·비즈니스 인증)의 모니터링까지 대신 수행. 별도 Meta Social Technologies MCP로 API 탐색·문서 검색·오류 해결 지원
- **의미**: 대형 플랫폼이 자사 서비스용 MCP를 직접 만드는 흐름(PayPal·Stripe·GitHub·Notion·Slack·Salesforce·Atlassian·X·구글·MS)의 연장선에서, 메타의 기존 라인업(광고 관리·앱 설정 모니터링)을 메시징 비즈니스 전반으로 확장 — 에이전트 도구 사용이 실험이 아니라 기본 경로가 됐다는 증거. 개발자 콘솔·비즈니스 매니저·API 레퍼런스를 오가던 수동 설정이 대화형 지시로 대체

### 25차 갱신 분석: "통합 계층의 양방향 확장 — 인프라는 묶고, 진입은 낮춘다"

| 도구 | 대상 접착 영역 | 해법 | 확장 방향 |
|------|--------------|------|----------|
| OSMO | 훈련·시뮬·실기 검증 사이 스크립트 | K8s 컨트롤 플레인 + 플랫폼 라우팅 | 위로 — 물리 AI 인프라 통합 |
| WhatsApp MCP | 콘솔·매니저·문서 사이 수동 설정 | MCP 서버 + 코딩 에이전트 | 아래로 — 비즈니스 운영 진입 |

1. **물리 AI 인프라의 민주화 동시 락인**: 3계층 파이프라인 구축이 대기업의 자체 인프라 역량이었으나 OSMO+Helm+KIND 퀵스타트로 중소 팀·연구실도 동일 워크플로 재현 가능 — [산업 동향](industry-trends.md) ③ 물리 세계 확장 축의 공급망 접근성 개선. 단 NVIDIA는 공개를 통해 전 계층 하드웨어 락인을 확보한다는 양면
2. **MCP의 '백오피스' 전환**: 지금까지 MCP는 개발 도구(브라우저·터미널·클라우드) 연결이 중심이었다면, WhatsApp MCP는 비즈니스 운영의 설정·유지보수 노동을 도구화 — MCP가 '개발자 도구 프로토콜'에서 '기업 운영 프로토콜'로 이동하는 관측점
3. **AGENTS.md·skills가 오픈소스 기대 사양으로**: OSMO가 저장소에 에이전트 안내문을 내장한 것처럼, 코딩 에이전트 조작 가능성이 대형 오픈소스 프로젝트의 배포 요건으로 굳어지는 흐름 — [22차](#2026년-9월-22차-갱신-에이전트-공급망의-3개-신생-계층--검증합성개인-데이터) '에이전트가 쓰는 도구' 논의의 물리·백오피스 확장

> 💡 **종합 교차 참조**: OSMO는 [프레임워크 동향](frameworks-overview.md)의 NVIDIA 스택(NemoClaw 7차·CUDA Rust 18차)에 오케스트레이션 계층을 완성하는 편이고, [7/28 MCP 무상태 스펙](../records/2026-07-29-mcp-spec-2026-07-28-stateless-protocol.md)이 확보한 K8s 확장성이 그 기반. WhatsApp MCP는 [산업 동향 29차](industry-trends.md) 메타 뮤즈의 '대리 실행'이 소비자 거래에서 기업 설정 영역으로 넘어간 버전. 관전 축: ① OSMO의 비-NVIDIA 하드웨어 백엔드 지원 여부(락인 해제 시험) ② WhatsApp MCP가 대리 설정의 실서비스 사례를 축적하는 속도 — [산업 33차](industry-trends.md) AIUC의 감사 대상에 '에이전트가 수행한 설정 작업'이 포함되는지도 흥미로운 교차점.

## 2026년 9월 26차 갱신: MCP 공급원의 양방향 확장 — 물리 공간과 국제기구 데이터

25차가 MCP의 '기업 운영 프로토콜' 전환(WhatsApp Business Tools)이었다면, 26차는 MCP로 연결할 수 있는 대상의 지도가 양쪽 끝으로 확장된 갱신이다. Google은 소비자의 물리 공간(Google Home)을, UN·구글은 국제기구의 권위 있는 통계(UN System Data Commons)를 각각 MCP로 열었다. 에이전트가 '행동할 대상'과 '근거할 데이터'가 같은 프로토콜 위에 올라온 셈이다.

### Google Home MCP 서버 — '집 제어권 위임'이 계정 공유가 아닌 프로토콜 차원으로 ⭐⭐⭐

**출처**: [TechCrunch](../records/2026-09-17-google-home-mcp-server-early-access.md) (9/16 발표)

- **내용**: MCP 지원 에이전트(Claude, Hermes, OpenClaw, ChatGPT, Google Antigravity)가 Google Home 기기를 제어하고 이벤트 기록에 접근 — 자연어로 카메라 요약 검토·스마트홈 활동 모니터링·연결 기기 제어·커스텀 대시보드 생성까지. Nest 도어벨·온도조절기는 물론 'Works with Google Home'(Matter) 인증 기기까지 포괄
- **권한 구조**: Google Cloud 프로젝트 생성 → Home MCP 사용 구성 → 구성 정보를 에이전트에 전달 → 에이전트가 OAuth 로그인·권한 부여 수행. '에이전트에게 집 제어권을 주는 일'이 **계정 공유가 아니라 프로토콜 차원의 위임**(Cloud 프로젝트+OAuth+에이전트별 권한 부여)으로 표준화되는 첫 대규모 사례
- **배포 조건**: 9/16부터 수주간, 미국 Google Home Premium Advanced(월 $20) 구독자부터. 다른 티어·시장 확장 시점은 코멘트 거부 — 에이전트 연동이 구독 상품화의 새 차별화 축임을 확인
- **범위의 의미**: 구글은 Cloud·데이터 플랫폼·Workspace에 이어 **소비자 물리 공간**을 MCP로 개방. 단순 온오프 제어가 아니라 카메라 요약·이벤트 히스토리 같은 **컨텍스트 소비**까지 열렸다는 점에서 컨텍스트형 소비자 에이전트의 토대가 된다

### UN System Data Commons — 국제기구 통계를 MCP로, 출처 추적과 함께 ⭐⭐⭐

**출처**: [TechCrunch + Google 공식 블로그](../records/2026-09-18-un-google-data-commons-mcp-agents.md) (9/17 발표)

- **배경 — 21.2% 벤치마크**: UNICEF가 글로벌 개발 지표 질문 13.3만 건으로 주요 LLM 6종(GPT-4o·GPT-4o-mini, Claude Sonnet 4.5·Haiku 4.5, Gemini 2.5 Flash·2.0 Flash)을 평가한 평균 정확도 **21.2%**. 응답 5건 중 3건은 애매한 표현으로 쓸 수 있는 숫자조차 없었고, 이틀 뒤 같은 질문에 두 번 모두 동일한 숫자를 준 경우는 절반 — 파라미터 지식만으로는 통계 영역이 사실상 불가능하다는 정량 입증
- **구조**: 구글 오픈소스 Data Commons 위에 UN 산하기관 통계를 'AI-ready 지식 그래프'(지표·시간축·지리 경계 정규화)로 통합 + 자연어 질의 + **MCP 서버**. 도구 호출 한 번으로 통계와 출처를 함께 반환하며, 검색 데이터를 원래 UN 자료로 되돌려 확인하는 **출처 추적** 내장
- **규모·목표**: UN 26개 기관 참여 약속(출시 시점 약 20개 기관 데이터), 2027년까지 UN 통계 데이터셋 80% 편입 목표. Google.org 인프라 200만 달러 지원, UN이 통치하는 인스턴스에서 운영. UNICEF 사이트 유입의 이미 10%가 AI 어시스턴트라는 관측도 함께 공개
- **의미**: '권위 있는 데이터'를 에이전트에 공급하는 표준 인프라를 국제기구 차원에서 처음 개방 — 에이전트 개발자는 데이터 파트너십 없이 공신력 자료를 도구로 붙일 수 있게 됨. **컨텍스트 공급자(MCP 서버)가 모델만큼 중요해진다**는 흐름의 공공 영역 확증. 구글 총괄의 "모델이 뉘앙스를 오해할 수 있으므로 사람이 반드시 검토해야 한다" 경계 표명도 기록 가치

### 26차 갱신 분석: "MCP 확산의 3단 지도 — 개발 도구 → 기업 운영 → 물리 공간·공공 데이터"

| 단계 | 사례 | 에이전트가 얻는 것 |
|------|------|------------------|
| 개발 도구 | 브라우저·터미널·클라우드 MCP | 작업 도구 |
| 기업 운영 (25차) | WhatsApp Business Tools MCP | 설정·유지보수 노동 |
| 물리 공간 (26차) | Google Home MCP | 집의 기기·영상·기록 |
| 공공 데이터 (26차) | UN System Data Commons | 검증된 통계+출처 |

1. **물리 제어권의 프로토콜 위임**: Google Home MCP의 OAuth+에이전트별 권한 부여 구조는 '에이전트에게 집을 맡기는 일'의 표준 인터페이스가 될 후보. 삼성 SmartThings·아마존 Alexa 등 타 생태계에 동종 개방 압력이 예상되며, 카메라·이벤트 기록 접근이 포함된 만큼 **첫 보안 사고가 설계를 재규정할** 관전점이다
2. **오픈소스 에이전트의 동등 접근**: 지원 예시에 **OpenClaw가 공식 명시**된 점이 기록 가치 — 셀프호스팅 개인 에이전트가 대형 플랫폼 기기와 동등하게 대화하는 시장이 열렸음을 뜻한다. [22차 Gemini Spark](#gemini-spark-구글-포토-라이브러리-관리--개인-데이터-위의-소비자-에이전트-)(플랫폼 종속 소비자 에이전트)와 대비되는 개방형 경로
3. **환각 대응의 '공급 측' 해법**: UN Data Commons는 검색 근거 부여(retrieval grounding)를 벤더 정책이 아닌 **국제기구 표준 인프라**로 제도화한다. 21.2%라는 정량 근거와 함께, 출처 추적이 기업 데이터 플랫폼·규제 프레임으로 확산될 선례 후보

> 💡 **종합 교차 참조**: Google Home MCP는 [산업 동향](industry-trends.md) 소비자 구독 상품화 축(Gemini Spark 22차·Premium Advanced 티어)과, UN Data Commons는 [연구 동향 17차](research-overview.md) Paper2Agent(지식 배포 단위를 MCP 서버로)와 각각 연결된다. [프레임워크 21차](frameworks-overview.md) Claude 통합(작업 분배를 에이전트가 결정)과 함께 보면, '에이전트가 무엇을 만지고 무엇을 근거로 삼는가'의 인터페이스가 같은 주에 물리·데이터·제품 3개 전선에서 동시 표준화되는 흐름. 관전 축(숙제 ㊶): ① Google Home의 타 구독 티어·시장 확장과 SmartThings·Alexa 대응 ② 물리 기기 제어 권한 위임의 첫 보안 사고 여부 ③ UN 80% 편입(2027) 진행 속도와 출처 추적의 기업 플랫폼 확산

### 4. Cua CUA-S1 — 컴퓨터 사용의 '국소 판단'을 706k 파라미터로 오프로드 ⭐⭐⭐⭐

- **경제성**: 컴퓨터 사용 에이전트의 비용·지연 대부분이 범용 LLM 호출에서 발생 — GUI 국소 결정의 소형 모델 오프로드는 16차 비용 3계층·24차 '호출 소거'(LangCache)에 이어 **'판단 오프로드'** 계열의 오픈 실증. Cua의 클라우드 데스크톱(Fleets)·드라이버·Cua Bench 결합 상업 모델은 오픈 연구 릴리스가 생태계 확보 전략과 맞물리는 구조

## 2026년 9월 28차 갱신: 인간-에이전트 접점의 3계층 — 음성 입력, 팀 채널, 설계 캔버스

27차가 에이전트와 맺는 '계약'의 조건(지시·권한·판단)이 정비된 갱신이었다면, 28차는 그 계약 아래 인간과 에이전트가 실제로 만나는 접점이 3개 층위에서 동시에 제안된 갱신이다. 입력 층위에서는 음성이 에이전트 워크플로의 시작 버튼이 되었고(ChatGPT 모바일), 협업 층위에서는 에이전트가 고유 신원과 수신함을 가진 팀원으로 채널에 입장했으며(Ando), 검토 층위에서는 인간과 에이전트가 같은 캔버스에서 설계를 검토하는 도구가 오픈소스로 나왔다(Whiteboard).

### 1. ChatGPT 모바일 음성 에이전트 — 워크 탭의 작업을 말로 시작 ⭐⭐⭐

**출처**: [TechCrunch](../records/2026-09-24-chatgpt-mobile-voice-agentic.md) (9/23 발표, 9/24 수집, major-media, 교차 확인 2)

- **내용**: Plus·Pro 구독자가 모바일 워크 탭에서 문서 작성·이메일 초안·Slack 메시지 요약 등 워크플로를 음성으로 시작. 7월 GPT-Live(대화형 음성 모델)→데스크톱 통합에 이은 모바일 확장. 사이트 제작·프레젠테이션 생성·클라우드 브라우저·금융 영역 접근 포함, Free·Go는 플러그인 연동 수준으로 차등 유지
- **연속성**: 모바일에서 시작한 대화를 데스크톱에서 이어서 작업 — 세션 상태의 클라우드 공유가 전제. "더 풍부한 텍스트 출력"은 음성 대화의 산출물이 단순 답변을 넘어 구조화된 문서로 진화 중이라는 신호
- **설계 철학 분기**: Anthropic은 9/16 Claude Chat·Cowork를 하나로 통합했고 OpenAI는 채팅과 워크스페이스를 여전히 분리 — 같은 '에이전트 작업' 시장에서 통합형 vs 분리형 UI의 방향이 갈라지는 관전점

### 2. Ando — 에이전트 네이티브 팀 메시징, 에이전트에게 신원과 수신함을 ⭐⭐⭐

**출처**: [TechCrunch](../records/2026-09-25-ando-agent-native-team-messaging.md) (9/24 발표, 9/25 수집, major-media, 교차 확인 2)

- **문제 정의**: MCP 서버 구축 경험의 창업자(Sara Du)가 반복 목격한 Slack 안 에이전트 장벽 — 메시지 왕복, 컨텍스트 전달, 토큰 예산 소모. "Slack과 Teams는 지나가버린 세계를 위해 만들어졌다" — 에이전트는 팀 참여자가 되어가는데도 설치형 앱으로 취급
- **설계**: 에이전트에 고유 신원·수신함 부여, 채널을 스스로 탐색해 참여 채널 선택, 태그 없이 대화에 끼어듦, 필요 시 승인을 기다리지 않고 사람에게 먼저 메시지. 채널·DM·그룹 대화에 더해 에이전트의 전사 통화 전사본 열람(라이브 콜) 지원. 'meat proxy'(에이전트 결과물을 사람이 팀에 대신 중계) 제거가 목표
- **조달·시장**: Accel·Index·Emergence 참여 프리시드+시드 $20M. 소프트웨어·부동산·금융 분야 15개국 고객과 함께하는 스텔스 탈출 — 가족 시장(Ollie·Fambot)과는 다른 팀 생산성 시장의 에이전트 협업 플랫폼 계열

### 3. Whiteboard — 설계 캔버스에서 만나는 인간과 에이전트 (오픈소스 IDE) ⭐⭐⭐

**출처**: [공식 사이트 + HN Show HN](../records/2026-09-25-whiteboard-open-source-agent-ide.md) (9/24 공개, YC W26, MIT, HN 158pt)

- **구조**: CodeOSS 기반 오픈소스 데스크톱 앱(macOS·리눅스) — 다이어그램 특정 노드 클릭→해당 코드로 이동, VSCode 키바인딩·LSP 호환. Claude Code·Codex 등 기존 코딩 에이전트를 연결해 에이전트가 캔버스에 작업 내용을 그림으로 설명하는 SDK 제공
- **핵심 기능**: ① Rust AST 기반 '의미론적 diff 뷰어' — 긴 함수는 의사코드로 요약, 단위 테스트·대규모 문서 변경은 접어서 숨김 ② '결정 로그(Decision Log)' — 에이전트가 자율적으로 내린 결정을 조회하고 자기 궤적을 화이트보드에 연결해 감사
- **동기·채택**: 에이전트 PR이 이해 없이 병합되며 쌓이는 '인지 부채(cognitive debt)' 해결이 동기 — Salesforce·Modal이 아키텍처 수준 변경 검토 도구로 이미 사용 중이라고 밝힘. 시퀀스 다이어그램·ER 다이어그램 수준의 리뷰로 코드 리뷰의 단위를 diff에서 설계로 올리는 시도

### 28차 갱신 분석: 접점의 3계층

| 계층 | 도구 | 접점의 단위 | 상태 |
|------|------|------------|------|
| 입력 | ChatGPT 모바일 음성 | 말 한마디 → 워크플로 | 대형 벤더 배포(Plus·Pro) |
| 협업 | Ando | 에이전트 = 신원·수신함 보유 팀원 | 스타트업 스텔스 탈출($20M) |
| 검토 | Whiteboard | 공유 캔버스의 설계 diff·결정 감사 | 오픈소스(MIT) 초입 |

1. **음성이 에이전트의 진입 인터페이스로**: 27차 권한 계층(가족·데스크톱 위임)에 이어 입력 계층이 음성으로 — [모델 동향 32차](models-overview.md) Flash TTS(목소리 설계)·[산업 동향 37차](industry-trends.md) 레이밴 오디오(카메라 없는 상시 접점)와 함께 음성 스택 3각의 도구편이 합류. 통합형(Anthropic) vs 분리형(OpenAI) UI 승부가 다음 관전점
2. **에이전트 신원의 협업 계열 확장**: 27차 구글 CC의 '자체 계정'이 가족 공간이었다면 Ando는 팀 채널 — 신원·수신함·채널 자가 선택·선제 메시지로 '에이전트를 일등 시민으로' 만드는 설계. Slack·Teams의 대응(에이전트 시민권 부여 vs 차단)이 협업 도구 시장의 다음 분기 화두
3. **검토 단위의 상승 — diff에서 설계로, 그리고 감사 로그**: 20차 승인 큐(통제 UI)·27차 AGENTS.md(지시 규약)에 이어, 화이트보드는 '무엇을 승인할 것인가'의 내용을 코드 diff가 아닌 설계 다이어그램으로 올리고 결정 궤적을 남긴다 — '인지 부채'라는 이름으로 에이전트 시대의 코드 리뷰 문제를 재정의

> 💡 **종합 교차 참조**: 세 도구는 모두 '에이전트가 하는 일을 인간이 어떻게 보고 맞추는가'라는 통제·관찰 축의 인터페이스편 — [프레임워크 동향](frameworks-overview.md)의 하네스·승인 설계와, [연구 동향 20차](research-overview.md) 스프린트의 '인간 승인 게이트' 운영과 짝을 이룬다. 관전 축(숙제 신설 78~79): ① Ando류 에이전트 신원·선제 메시지의 표준화 여부와 Slack·Teams 대응, 'meat proxy' 제거의 실측 ② Whiteboard류 설계 리뷰 도구의 채택 확산과 '결정 로그'의 에이전트 감사 관행 표준화 여부

## 2026년 9월 29차 갱신: 계약의 하부구조 — 조달 기준표와 대역 외 감시

28차가 인간-에이전트 접점(음성·채널·캔버스)을 기록했다면, 29차는 그 접점 아래 깔리는 계약·통제의 하부구조가 동시 공개된 갱신이다. 도구를 사는 조직의 질문(누가 배상하나·프롬프트는 어디에 있나·500석은 얼마인가)에 답하는 첫 계약 기준표가 나왔고, 도구를 가두는 문제(런타임 밖에서 밀리초 격리)에 하드웨어 벤더가 답했다.

### 1. 기업용 AI 코딩 에이전트 계약 비교 — 배상·데이터 소재·감사가 경쟁 축으로 ⭐⭐⭐⭐ (이월 처리)

- **500석 실비용·과금 전환**: Copilot Business $9,500(Enterprise Cloud 포함 시 $20,000)·Kiro Pro $10,000·Cursor Teams $20,000·Cognition은 200명 상한(500석은 엔터프라이즈 견적 필요). Copilot은 6/1부 사용량 기반 크레딧제(1크레딧=$0.01, Kiro 추가 크레딧 $0.04) — 좌석 수가 아니라 **사용량 모델링**이 조달 검토의 표준 항목으로
- **의미**: 27차 '계약 3계층'(지시·권한·판단)에 **조달 계약 제4계층**이 합류. 기능 로드맵과 별개로 계약상 보증 범위를 엔지니어링 산출물처럼 관리해야 하며, 무상한 배상+SSO+리전 선택을 갖춘 대형 플랫폼에 유리한 재편 압력과 오더폼 협상이라는 조달 마찰이 동시 발생

### 2. NVIDIA Open Agent Safety Platform — 런타임 밖 DPU에서 밀리초 격리 ⭐⭐⭐
